# Profile

A structured, persistent source of truth for a person's experiences. The first version captures software development experience through coding-agent skills, both ongoing (after a piece of work) and retrospective (from existing repos), and saves approved records through an MCP server into PostgreSQL. The scope is capture only: no résumés, portfolios or other consumption yet.

The plan is `docs/roadmap.md`: the remaining dev work, in order. The planning docs it was built from are archived in `docs/plan/archive/`.

## How we work

This project is augmented manual programming: Claude does most of the implementation, while the user keeps architectural direction and understanding.

1. Discuss the intended behavior and design.
2. Claude implements a small, reviewable change.
3. The user inspects the code and questions unfamiliar decisions.
4. Refine or refactor as needed.
5. Claude writes and runs appropriate tests.
6. The user reviews and commits.

- Do what was asked, one small change at a time. Don't run ahead into the next step.
- Challenge assumptions and keep scope small. No process or infrastructure for its own sake.

## Stack

- Node 24, pinned with pnpm's `devEngines.runtime`. pnpm downloads it and uses it for every `pnpm` command and the git hook. Plain `node` in the shell may be a different version.
- pnpm 12, ESM, TypeScript, Vitest, ESLint, Prettier, Husky with lint-staged.
- zod for domain schemas.
- Persistence: PostgreSQL in Docker Compose, with Drizzle ORM, drizzle-kit migrations and a separate throwaway test database.
- `module: nodenext`: imports use `.js` extensions in `.ts` files.
- Imports use the `#` aliases from `package.json`'s `"imports"` field, never relative paths: `#src/…`, `#tests/…`, `#config/…`, `#scripts/…` (for example `import { connectDatabase } from "#src/db/client.js"`). `#src` points at `dist/` under the `production` condition, which `pnpm start` sets, and at `src/` everywhere else.

### TypeScript 6/7 workaround

TS 7 (the native compiler) has no JS API yet, so typescript-eslint can't use it. Following Microsoft's guide, there are two installs:

- `@typescript/native` is TS 7. It provides `tsc`, used by `build` and `typecheck`.
- `typescript` is an alias for `@typescript/typescript6` (TS 6.0), used by typescript-eslint.

Remove the aliases once typescript-eslint supports TS 7.1+. The remaining peer warning about `@typescript/native` wanting 7.1 is expected.

## Layout

- `src/`: application code, compiled to `dist/` by `tsconfig.build.json`.
  - `src/config.ts`: app settings (for example the database connection timeout). Tooling config lives in `config/` instead, which isn't part of the build.
  - `src/db/client.ts`: `connectDatabase(url)`, the shared Postgres connection for services.
  - `src/db/schema.ts`: Drizzle table definitions, the source of truth for the data shape (`snakeCase` tables: camelCase in TS, snake_case columns).
  - `src/domain/`: zod schemas derived from the tables with `drizzle-orm/zod` (`Experience`, `NewExperience`, `Profile`), plus their inferred types. Don't hand-write shapes here; change the table instead.
    - `errors.ts`: `ValidationError` (bad input, one problem per line) and `NotFoundError` (missing, or in another profile).
  - `src/services/`: the operations callers use, each taking the open `db` first. `experience.ts` has save, list, get, update and delete, all scoped to a profile; `profile.ts` has `resolveProfile`.
    - `lib/`: helpers shared by services, not services themselves. `lookup.ts` has `isUuid` and `ownedExperience` (the "this experience, only within this profile" condition).
- `docs/`: project documents.
  - `roadmap.md`: the remaining dev work, in order: numbered steps with lettered items. Finished items are deleted (git keeps the history). Updated by `/consume-plans`.
  - `plan/`: the queue of planning docs waiting to be consumed into the roadmap. `/consume-plans` runs `/grill-me` on everything in it, writes what you confirm to the roadmap, and moves consumed docs to `plan/archive/` as `<YYYY-MM-DD>-<name>.md`.
- `tests/`: Vitest tests (`*.test.ts`). `tests/smoke.test.ts` (`1 + 1 = 2`) stays permanently.
  - `tests/db/`: database tests, run only by `pnpm test:db`. `setup.ts` is their global setup: it starts the throwaway Postgres, migrates it, provides its URL (`inject("databaseUrl")`) and removes it afterwards.
    - `reset.ts`: `resetDatabase(db)` empties every table; call it in `beforeEach` in DB test files.
- `config/`: tooling config.
  - `lint-staged.ts`, and `drizzle.ts` for drizzle-kit.
  - `vitest.ts` for unit tests (everything except `tests/db/`) and `vitest-db.ts` for DB tests. `vitest-db.ts` also holds `testDatabase`: its URL, plus `keepAfterRun` (set it to `true` to keep the test database for inspecting with psql).
- `compose.test.yml`: the throwaway test Postgres (project `profile-test`, port 5433, data in memory, fixed non-secret credentials).
- `migrations/`: SQL migrations generated by drizzle-kit. Review before applying; never edit one that has been applied. Prettier ignores this folder.
- `scripts/`: dev scripts run with tsx.
  - `dev.ts` starts Postgres, then the app.
  - `check-migrations.ts` runs a drizzle-kit dry run to catch schema changes without a migration.
  - `lib/`: helpers shared by scripts and tests, not run directly. `compose.ts` has `runCompose(args)`, which runs `docker compose` and returns the result without printing or throwing.
- `tsconfig.json`: type-checking only (`noEmit`). Covers `src`, `tests`, `config`, `scripts` and `eslint.config.ts`.

## Commands

- `pnpm dev`: start the Postgres container (waiting until it's healthy), then run `src/index.ts` with tsx, restarting on save (no type-checking). `docker compose down` stops the database and keeps its data.
- `pnpm db:generate`: generate a SQL migration in `migrations/` from changes to `src/db/schema.ts`
- `pnpm db:migrate`: apply pending migrations to the database in `DATABASE_URL`
- `pnpm db:check`: fail if `src/db/schema.ts` has changes without a migration (a dry run; no database needed)
- `pnpm db:studio`: browse and edit the data in Drizzle Studio (local server on 127.0.0.1:4983, opened at local.drizzle.studio)
- `pnpm db:psql`: open an interactive psql session in the Postgres container (`\q` to quit)
- `pnpm test`: run the unit tests once (no Docker needed)
- `pnpm test:db`: start the throwaway Postgres on port 5433, migrate it, run `tests/db/`, then remove it (needs Colima running)
- `pnpm typecheck`: type-check everything
- `pnpm lint`: ESLint
- `pnpm format` / `pnpm format:check`: Prettier, writing fixes or only checking
- `pnpm build`: compile `src/` to `dist/`
- `pnpm start`: run `dist/index.js`

The pre-commit hook (`.husky/pre-commit`) runs lint-staged (ESLint and Prettier fixes on staged files), then `pnpm typecheck`, `pnpm db:check` and `pnpm test`. It doesn't run `pnpm test:db`, so run that yourself before committing changes to persistence.

## Privacy

The GitHub repo is public. Never commit secrets, personal data or captured experience records. `*.db` and `.env*` are gitignored.
